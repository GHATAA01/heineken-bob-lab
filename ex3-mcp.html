Exercise 3 — Both Tracks

Connect Bob to a Live System

Add one JSON block. Bob calls a real external API. No enterprise approval needed.

⏱ 10 minutes 👥 Everyone
🏠 Start 1 · Basics 2A · BW 2B · Databricks 3 · MCP ⭐ Finale

? What is an MCP?

An MCP (Model Context Protocol) server is a small bridge that lets Bob call external systems — databases, APIs, ticketing tools, cloud platforms — directly from a conversation.

Instead of copy-pasting data from a system into Bob, Bob fetches it live. The connection is configured once in a JSON file. After that, it just works.

💡 In production, this is how Bob connects to Databricks, JIRA, and Azure DevOps. Today we'll use a free public API so you can experience the same thing with zero setup.

1 Check Your MCP Config

Your starter kit already has a .bob/mcp.json file with the Open-Meteo weather API pre-wired (Path B). Open it in VS Code to verify:

  1. In the VS Code file explorer (left panel), click the arrow next to .bob/ to expand it
  2. Click mcp.json to open it
  3. You should see a "weather" server entry with the Open-Meteo URL
✅ If you see the "weather" entry — you're ready. Skip to Step 2.
⚠️ If the file is empty or missing — copy the block below into .bob/mcp.json and save: 
{
  "mcpServers": {
    "weather": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-fetch"],
      "env": {
        "FETCH_BASE_URL": "https://api.open-meteo.com"
      },
      "alwaysAllow": ["fetch"]
    }
  }
}

2 Choose Your Path

Both paths teach the same thing. Pick the one that works for your setup:

🌤️

Path B — Open-Meteo Weather

No account. No internet restrictions. Works on any network. Recommended for everyone.

🐙

Path A — GitHub Public API

Needs internet access to GitHub. No account required for public endpoints. Good if you have GitHub access.

2B Path B — Weather API Recommended

Prompt 1 — Fetch live weather

Open a new Bob chat and type:

Type this in the Bob chat:

Use the weather MCP to fetch the current weather in Amsterdam. The endpoint is: /v1/forecast?latitude=52.37&longitude=4.90¤t_weather=true
What is the current temperature and weather condition?
✅ You should see — Bob calls the API and returns the current temperature in Amsterdam (Heineken HQ) and a weather condition code. Watch the MCP tool badge light up in the Bob panel.

Prompt 2 — Use live data in professional writing

Type this in the Bob chat:

The current weather at Heineken's Amsterdam office is [temperature from above]. I'm writing a short project status update for stakeholders in Amsterdam. Add a friendly one-line weather greeting at the top of this message:

"The COPA migration is on track. We completed the BW Discovery phase this week and have identified 38 migration stories for the upcoming sprint."
✅ You should see — Bob adds a personalised weather greeting (e.g. "Hope you're keeping warm in Amsterdam today at 8°C!") to your professional update.
💡 This is a simple example — but the principle is the same as Bob fetching live data from Databricks, JIRA, or SAP. Real-time context, no copy-pasting.

2A Path A — GitHub API Optional

Update your MCP config for GitHub

Add this server entry to your .bob/mcp.json (inside the mcpServers block, alongside the weather entry):

    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-fetch"],
      "env": {
        "FETCH_BASE_URL": "https://api.github.com"
      },
      "alwaysAllow": ["fetch"]
    }

Save the file. Bob will detect the new server automatically.

Prompt 1 — Fetch latest Delta Lake release

Type this in the Bob chat:

Use the github MCP to fetch the latest release of the delta-io/delta repository. The endpoint is: /repos/delta-io/delta/releases/latest
What is the latest version number?
✅ You should see — the latest Delta Lake version number fetched live from GitHub (e.g. "Delta Lake 3.3.0").

Prompt 2 — Combine with your migration context

Type this in the Bob chat:

I am migrating from SAP BW to Databricks. The latest Delta Lake version is [version from above]. What are the top 3 new features in this version that are most relevant to a BW migration project? Keep each point to one sentence.
✅ You should see — three concise, migration-relevant feature highlights combining the live version data with Bob's knowledge of Delta Lake and BW migration patterns.
🐙 Don't have a GitHub account? Create one free in 2 minutes

You don't need this today — the public API works without an account. But a free GitHub account is worth having.

  1. Go to github.com/signup
  2. Enter any personal email — the free tier is all you need
  3. Choose a username and verify your email
  4. Done — the GitHub API works immediately
💡 Why it's useful: You can store your Bob workspace rules and skills in a GitHub repo and share them with your whole team. One repo = one consistent Bob setup for everyone.

⚠️ This is completely optional. Use Path B (Weather) if you prefer.

💡 What Both Paths Prove

Whether you fetched weather data or a GitHub release — you just connected Bob to a live external system with one JSON block and no enterprise approval.

In a real project, the same pattern connects Bob to:

  • Databricks — query Unity Catalog, monitor pipeline runs
  • JIRA — read and create tickets from a conversation
  • Azure DevOps — link stories to pull requests
  • SAP BW — fetch metadata without extracting files
